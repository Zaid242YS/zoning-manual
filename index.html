1 · What this app does

This application helps homeowners, project managers and consultants organize evidence against a historical DeKalb County residential zoning review checklist. It provides separate views for (1) new house development, (2) additions and (3) alterations/repairs. It is designed to ask what is known, show what is missing and highlight what needs to be corrected or referred to County staff.

Important boundary: This is not a County application, official certification, complete code audit, engineering review or legal opinion. The County must confirm current requirements, zoning and approved variances. The uploaded source is a five-page checklist with a 2017 revision reference; it is not proof that each numerical rule remains unchanged in 2026.

2 · First-time use: exact steps

Step 1 — Open the files together

Save index.html and user-manual.html in the same directory. Double-click index.html to use it locally, or deploy both to the same GitHub repository linked with Vercel. The manual button on the sidebar opens user-manual.html.

Step 2 — Complete Property profile

Select 02 · Property profile. Enter the address, parcel number (if known), zoning district, project category and review date. Choose Unincorporated DeKalb County verified only after confirming jurisdiction; incorporated cities may use different procedures. Enter overlay or historic information in Property context.

Step 3 — Select the correct project type

Use New house, Addition, or Alteration/repair. This changes which historic checklist items appear. If your work spans two types, prepare separate records/backups or ask County staff to identify the proper permit path.

Step 4 — Begin checklist review

Open 03 · Compliance checklist. Each row contains a requirement, planning weight, status, evidence reference, notes, N/A rationale and an expandable response/variance area. Search a keyword or filter unresolved entries to navigate.

Step 5 — Select one status per item

Review actual documentation before selecting Compliant — evidence reviewed. Choose Noncompliant if a reviewed item fails; Missing / insufficient evidence if you need documents; Not yet reviewed if examination has not begun; and Not applicable only with a written reason. Unsupported N/A remains unresolved and affects the score.

Step 6 — Document your proof

Record site-plan sheet numbers, measurements, permit document names, contractor license verification, County correspondence, or code sections in the Evidence field. Notes should summarize what was checked and what remains uncertain. The tool tracks references; it does not upload or store attachments.

Step 7 — Handle any noncompliance

Open the row's Response / variance / appeal notes, or use sidebar 04 · Variances & appeals. Choose a response path such as revising plans, consulting staff, or requesting a variance pre-application. Enter the specific requested relief, case number if assigned, County outcome, next action and a personal planning date.

Step 8 — Review the dashboard

Go to 01 · Overview & score. Inspect the weighted compliance score, decision coverage, noncompliance count and missing/unreviewed count. The numerical target is 95%–100%, but an open critical requirement may prevent readiness regardless of the percentage.

Step 9 — Generate your confidential report

Select 05 · Reports & records. Review the full checklist evidence log and appeal tracker, then click Print / Save PDF. In the browser print window, choose Save as PDF as the destination. You may alternatively download an HTML report that opens independently.

Step 10 — Save a backup and protect privacy

Click Download JSON backup to preserve a portable editable copy. Later use Import saved JSON to restore it. The application also saves changes automatically to this browser's local storage. Keep files on an access-controlled device; local storage and JSON downloads are not encrypted. Never rely solely on browser storage for important projects.

3 · Understanding scoring and thresholds

The following planning weights are an original Creed to Commerce method, not official DeKalb requirements:

ClassificationWeightReason
Critical5Potentially foundational to eligibility, safety, permits or property constraints
High3Substantive review and documentary readiness
Standard1Additional administrative completeness

Conservative score = (sum of weights for items marked Compliant) ÷ (sum of weights of all applicable items) × 100. Items marked Noncompliant, Missing or Not yet reviewed score zero. Items marked Not applicable are removed from the denominator only if the user explains why.

Decision coverage = reviewed yes/no items ÷ all items except justified N/A × 100. Decision coverage is not the compliance score: it measures whether the checklist has been investigated, not whether it passed.

Example: If the applicable weights total 100 and verified compliant items total 96, the score is 96%. If even one significant condition is not satisfied, a 96% score does not create permission to build. In practice, approval requires meeting all applicable requirements or receiving appropriate formal relief.

4 · Variances, appeals and correction paths

SituationRecommended workflow
Evidence missingGather the survey, permit, dimensional calculation or agency response before concluding compliance.
Plan fails a current dimensional ruleFirst consider redesign; then consult DeKalb zoning staff to determine whether a variance is legally available.
Variance preparationRecord hardship facts, minimal relief requested, site plans, correspondence and assigned application number. A pending variance is not approval.
Adverse decisionDetermine with staff or counsel whether an administrative appeal, board review or judicial review is appropriate and confirm the legally applicable filing deadline. Do not use the app's reminder date as a statutory deadline.
Denied applicationDo not assume repeated filings or continued construction are permitted. Seek direct advice under the governing ordinance and the decision order.

The County's Zoning Board of Appeals page describes a pre-application process and differentiated relief. A variance can adjust some dimensional standards but does not change the allowed land use or zoning classification.

5 · Reports, privacy and managing records

  • Autosave: The app stores the current assessment in the browser using localStorage. Browser clearing, private browsing or switching computers may lose it.
  • JSON backup: Exports all entered data to one plain-text, unencrypted file. Protect it and avoid email forwarding without assessing confidentiality.
  • Import: Restores a prior JSON export, replacing the current assessment after confirmation.
  • PDF: Browser printing creates the PDF; there is no external PDF server.
  • Standalone HTML report: Exports readable results without needing the app. Like the PDF, it contains the private information entered.
  • Clear all stored data: Removes current local browser data after confirmation. It does not delete already downloaded files.
  • No uploads: The app has no server-side database, email submission or official County integration. Links to County pages open externally when clicked.

6 · Troubleshooting

ProblemAction
Percentage is lower than expectedCheck unreviewed and missing items. They count as zero; an N/A without an explanation remains unresolved.
Checklist changes unexpectedlyConfirm your project category. Each category displays its own applicable items; data from the other categories is retained.
PDF does not appearUse the browser's print dialog, select “Save as PDF,” and choose a local file destination.
Changes disappearedCheck whether browser site storage was disabled or cleared; restore your last JSON backup.
Manual button fails on VercelConfirm both filenames are located together, with index.html at the site root.
County rules conflict with checklist wordingFollow the current adopted rules and verified staff guidance; record the discrepancy in Notes.

7 · Deployment: GitHub and Vercel

  1. Make a new folder named dekalb-zoning on your computer.
  2. Put the two HTML files inside it and ensure the application is named exactly index.html and the guide user-manual.html.
  3. On GitHub, create a new repository. Upload both files into the repository root and commit.
  4. On Vercel, choose Add New → Project, import the GitHub repository and choose the default static deployment (no build command needed).
  5. Deploy and visit your Vercel address. Test navigation, sample self-assessment values, local saving, JSON export/import, PDF printing and clearing.
  6. Remember: Vercel hosts the app code, but the individual assessment data remains in each visitor's browser unless users choose to export or share it.
